## 8. Key Technology Patterns Observed

### Low-Latency Infrastructure
- **AVX-512 SIMD** — lubluniky/bs-p uses AVX-512 for market-making calculations
- **BMI2 hardware instructions** — OctopusTakopi/glass-rs leverages x86-64 BMI2 for orderbook traversal
- **Lock-free SPSC queues** — QuantDreamGit/HFT-LimitOrderBook uses cache-line aligned ring buffers
- **Zero-copy processing** — QuantDreamGit uses mmap + epoll; lubluniky/backtesting-kernel uses zero-copy NumPy
- **SoA (Struct-of-Arrays)** — DylanSiegel designs vectorization-friendly binary formats

### Language Distribution
- **Rust** dominates: glass-rs, binance_l3_est, OpenBook, crypto-crawler-rs, hyperliquid SDKs, polymarket-botkit
- **C/C++** for kernel-level performance: bs-p (AVX-512), backtesting-kernel, HFT-LimitOrderBook
- **Go** for network services: DylanSiegel's microstructure tools, hedgehog, polymarket-botkit dashboard
- **Python** for analysis layer: VPIN, backtesting API, ML models

### Data Architecture
- **TimescaleDB** — lubluniky/polymarket-botkit uses hypertables for time-series metrics
- **ClickHouse** — QuantDreamGit/HFT-LimitOrderBook for columnar analytics (250-400K rows/sec)
- **Databento DBN** — QuantDreamGit uses Databento's binary format for market data
- **SBE (Simple Binary Encoding)** — OctopusTakopi/sbe-collector (likely CME/exchange native format)

### Visualization Stack
- **egui/eframe** — DegenSugarBoo/OpenBook and cross-ex-arb-dashboard (Rust native desktop)
- **ratatui** — DegenSugarBoo/cli_ob, lubluniky/pingoblin (terminal UIs)
- **uPlot** — lubluniky/polymarket-botkit monitoring dashboard
- **PlotlyJS** — lubluniky/priceaction interactive dashboard

## 12. Architecture Insights for Our App

### From lubluniky's polymarket-botkit:
- **Ring buffer primitives in C** for zero-copy time-series (35M ops/sec)
- **Rust for risk/execution** with 100% test coverage
- **Go for monitoring dashboard** with uPlot WebSocket streaming
- **TimescaleDB** with hypertables and automated retention policies
- **Token-bucket rate limiting** for exchange API compliance

### From QuantDreamGit's HFT-LimitOrderBook:
- **4-thread pipeline**: Streamer → Decoder → LOB → Storage
- **Lock-free SPSC** between threads eliminates contention
- **Cache-line alignment** critical for performance
- **ClickHouse** for columnar analytics at scale

### From OctopusTakopi's glass-rs:
- **Radix trie** with 6-level fixed depth beats balanced trees for orderbook operations
- **Cached traversal paths** exploit sequential locality (orders cluster near BBO)
- **Linked leaf nodes** enable O(1) price level navigation
- **BMI2/LZCNT** hardware instructions for bit manipulation

### From DegenSugarBoo's OpenBook:
- **egui/eframe** viable for real-time financial visualization
- **Separation of concerns**: tokio background runtime + UI thread with immutable snapshots
- **egui_tiles** for dockable workspace management
- **Memory concern**: 600MB for single-market depth — WebGL/Canvas may be better for web
